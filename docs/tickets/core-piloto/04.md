## What to build

Criação administrativa da escola, responsável inicial e configurações básicas, com isolamento demonstrado entre duas escolas.

Esta é a fatia 04 do core aprovado. Aplicam-se as regras transversais da especificação principal; não há autorização para dados reais ou contratação implícita.

## Acceptance criteria

- [ ] Operador autorizado provisiona escola piloto sem pagamento e sem receber leitura padrão de conteúdo escolar.
- [ ] Responsável inicial e configuração de nome, fuso, ano letivo e nomenclaturas são explícitos, persistidos e auditados.
- [ ] Uma organização representa uma escola, mesmo sob mantenedora comum; apenas identidades/sessões são globais.
- [ ] Duas escolas sintéticas têm configurações independentes, e leitura/escrita por IDs manipulados não cruza organização.
- [ ] Operação tem interface aplicável e contrato HTTP validado, com testes contra PostgreSQL real; nenhuma condição de dados reais é considerada cumprida só por criar a escola.
- [ ] Entrega demonstrável/verificável pela fronteira pública: persistência, API, interface aplicável e testes comportamentais, com isolamento, autorização e auditoria desde o recurso entregue.
- [ ] Seguir arquitetura e referências de UI do PRD/spec quando aplicáveis; documentar checks realmente executados e pendências, sem substituir integração real por mocks ou declarar passos não realizados.
