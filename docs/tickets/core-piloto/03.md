## What to build

Inscrição e verificação de MFA, exigida para os perfis definidos no PRD.

Esta é a fatia 03 do core aprovado. Aplicam-se as regras transversais da especificação principal; não há autorização para dados reais ou contratação implícita.

## Acceptance criteria

- [ ] Profissional pode inscrever e verificar MFA pelo fluxo suportado do provedor validado, sem segredos em logs ou bundle.
- [ ] Operações de administração privilegiada e leitura restrita não são autorizadas sem satisfazer MFA, mesmo por chamada direta à API.
- [ ] Fluxo apresenta estados de inscrição, verificação inválida e acesso negado sem perda da proteção; sessão antiga não contorna a exigência.
- [ ] Testes HTTP e jornada web cobrem usuário sem MFA, com MFA válida e desafio inválido; registrar limitações operacionais reais, sem presumir recuperação de conta não validada.
- [ ] Entrega demonstrável/verificável pela fronteira pública: persistência, API, interface aplicável e testes comportamentais, com isolamento, autorização e auditoria desde o recurso entregue.
- [ ] Seguir arquitetura e referências de UI do PRD/spec quando aplicáveis; documentar checks realmente executados e pendências, sem substituir integração real por mocks ou declarar passos não realizados.
