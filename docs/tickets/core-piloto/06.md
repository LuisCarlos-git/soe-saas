## What to build

Pessoa vinculada a duas escolas troca de contexto sem reaproveitar dados, permissões ou respostas tardias da anterior.

Esta é a fatia 06 do core aprovado. Aplicam-se as regras transversais da especificação principal; não há autorização para dados reais ou contratação implícita.

## Acceptance criteria

- [ ] Usuário com vários vínculos escolhe escola ativa explicitamente e vê apenas contextos autorizados.
- [ ] Troca cancela requisições e descarta cache anterior; resposta tardia não reaparece no novo contexto. Logout também limpa o contexto.
- [ ] Query keys incluem organização e contexto de sessão/permissão; SSR mantém instâncias por requisição e não usa cache público autenticado.
- [ ] Nenhum relato é persistido em localStorage/IndexedDB; acesso via alteração de organização na URL é revalidado pela API.
- [ ] Playwright e integração HTTP cobrem alternância rápida entre duas escolas e sessões simultâneas sem vazamento.
- [ ] Entrega demonstrável/verificável pela fronteira pública: persistência, API, interface aplicável e testes comportamentais, com isolamento, autorização e auditoria desde o recurso entregue.
- [ ] Seguir arquitetura e referências de UI do PRD/spec quando aplicáveis; documentar checks realmente executados e pendências, sem substituir integração real por mocks ou declarar passos não realizados.
